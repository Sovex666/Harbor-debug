## Build a Windows debug executable

Prerequisites: Windows 10/11, Node.js 22+, pnpm 11, Rust stable with the MSVC
toolchain, Visual Studio Build Tools with Desktop C++ workload, and WebView2
Runtime, Git for Windows (Bash on PATH), and a JDK 17+ for Capstan staging.

From the repository root in PowerShell:

```powershell
pnpm install --frozen-lockfile
pnpm run setup
pnpm tauri build --debug --bundles nsis
```

The NSIS debug installer is produced under
`src-tauri/target/debug/bundle/nsis/`; the application executable is
`src-tauri/target/debug/harbor.exe`. For a directly runnable debug app without an
installer:

```powershell
pnpm tauri build --debug --no-bundle
```

Do not transfer only `harbor.exe`: the app also needs its DLLs, sidecars, and
resource directories. Prefer the installer for transfer.

Do not use the macOS generated binaries from another checkout. `setup:libmpv`
downloads and verifies the Windows `libmpv-2.dll`; `setup:binaries` fetches the
Windows sidecars required by the Tauri config.

## Run with diagnostics enabled

Close other Harbor instances first, then run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev-diag.ps1
```

In another PowerShell window:

```powershell
node scripts/harbor-diag.mjs pages
node scripts/harbor-diag.mjs state
node scripts/harbor-diag.mjs perf
node scripts/harbor-diag.mjs navigate calendar
node scripts/harbor-diag.mjs watch 30 5
```

The MCP server is:

```powershell
node scripts/harbor-diag-mcp.mjs
```

It exposes safe state/performance/image/navigation tools. Arbitrary evaluation
and heap snapshots require `HARBOR_DIAG_UNSAFE=1` and should stay disabled for
normal bug capture.

## Reproduce the reported Windows issue

1. Start a clean diagnostics session and export the player log once.
2. Play the same anime source without interacting for at least one episode.
3. Record wall-clock time and media position for every freeze or stop/restart.
4. Export after playing another video. The export must contain both sessions.
5. Run `node scripts/harbor-diag.mjs state` after the symptom and preserve the
   output with the exported log.

The new log contains timestamped session/lifecycle events, buffering/cache
transitions, periodic position samples, frame-drop counters, audio reload and
resync causes, and frontend numeric diagnostics. Stream URLs, credentials,
local paths, and titles are scrubbed.

Pay special attention to these lines:

- `reload cause=...`: identifies Harbor-triggered reloads.
- `playback:wake-reconnect`: only emitted after a timer gap followed by a
  confirmed stalled position; healthy playback advancing during WebView timer
  throttling must not reload.
- `playback:audio-resync`: identifies output reload position restoration.
- `finished playback, success (reason 2)`: mpv stop reason; correlate it with
  preceding `stop-request`, command, window, or network events.
- `Audio device underrun detected` and HTTP/2 receive errors: these may explain
  a freeze without proving Harbor initiated a reload.
